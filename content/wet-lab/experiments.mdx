<Section id="overview" title="Experimental plan" kicker="01">

Experiments are organised around AURA's five DBTL cycles. Each assay answers a specific question before we commit to the next design. This page is the map; protocols and the notebook hold the detail.

<Callout variant="note" title="Status">
  Some runs are scheduled or in progress. Results land on the Results page as data arrives.
</Callout>

</Section>

<Section id="goals" title="Goals" kicker="02">

1. Confirm that a chosen host-response marker can be detected in milk matrix
2. Characterise recognition-module binding specificity
3. Measure circuit leakiness, dynamic range, and time-to-signal
4. Validate end-to-end readout on a strip prototype
5. Compare exploratory output against SCC / culture references where samples allow

</Section>

<Section id="assays" title="Assay pipeline" kicker="03">

| Phase | Assay | Question |
| --- | --- | --- |
| 1 | Literature + spiking design | Which marker window is realistic? |
| 2 | Binding screen | Does recognition work in milk? |
| 3 | Expression / cell-free run | Does the circuit report? |
| 4 | Dose–response | What is dynamic range and EC₅₀? |
| 5 | Strip end-to-end | Can a non-specialist read the output? |

</Section>

<Section id="controls" title="Controls" kicker="04">

Every experiment includes positive controls (known marker or induced signal), negative controls (unspiked milk, irrelevant protein), and matrix blanks. Strip tests always include a control line.

</Section>

<Section id="samples" title="Samples" kicker="05">

Development uses spiked milk panels prepared under documented conditions. Any comparison to field samples requires veterinary oversight and is exploratory only — not a clinical validation study.
